# Owner decision packet

Status: `PROPOSED_OWNER_REVIEW`

This packet proposes the next empirical step. It authorizes no model call, repository publication, or outcome claim.

## The question

The most useful economic comparison is the approved-card route against the same lower-cost worker receiving full history. Both conditions begin with the same two-minute, read-only frontier preflight. One then transfers the full context; the other transfers the approved card. This directly tests whether Clutch adds value beyond an ordinary model switch.

The frontier-full condition remains important as a quality anchor. It answers a different question: how the complete lower-cost route compares with leaving the frontier model engaged for the whole build. The two comparisons must be reported separately.

The automatically generated card is also a combined intervention. It may compress, reorganize, omit, or improve context. Calling that contrast pure compression would give the card generator credit or blame that the experiment cannot separate.

## The independent unit

One 30-minute build session is one task. Inside it, a prompt arrives every five minutes and changes the project state. Those six transitions measure continuity under stress, but they share history and cannot be counted as six independent samples. Repeated random seeds are sensitivity checks for the same reason.

Every condition starts from an identical workspace digest, tool set, permission set, hidden checks, frontier preflight, and time budget. The condition order is recorded and counterbalanced. Each condition gets one attempt.

## Recommended first stage

Run five independent shakedown tasks, one from each proposed task class, using `gpt-5.6-sol` for the identical read-only preflight and `gpt-5.6-terra` as the first worker under test. Four conditions per task produce 20 runs. At 30 minutes each, the maximum agent time is 10 hours.

This stage tests the measuring equipment. It must prove that clean resets, model transitions, condition order, token classes, provider charges, review time, task scoring, and complete route costs are recorded correctly. It produces descriptive data only. Five tasks cannot establish savings, quality preservation, resilience, or human-review effectiveness.

The `gpt-5.6-luna` block should run later as a separate replication. Pooling Terra and Luna would blur model capability with the card effect.

## Why the final sample is still open

The required sample depends heavily on two owner choices: the maximum acceptable quality loss and the rate at which the paired conditions disagree. The included planning approximation assumes no true quality difference and 80 percent power.

| Quality margin | Paired discordance | Counterbalanced tasks | Four-arm agent time |
|---|---:|---:|---:|
| 5 percentage points | 10% | 248 | 496 hours |
| 10 percentage points | 10% | 64 | 128 hours |
| 15 percentage points | 10% | 28 | 56 hours |

These numbers apply to one adequately powered task population and one worker block. Separately powering several critical strata or repeating the study with Luna multiplies the requirement. The five-task shakedown should estimate discordance and data quality before the owner chooses this expense.

The approximation is a planning aid. The final preregistration still requires a frozen simulation using the selected tasks, primary comparison, quality margin, and exact analysis. A convenient small sample will remain descriptive if it does not meet that requirement.

## Cost accounting

Every condition must include all provider calls made for that route. For Clutch, that includes frontier preflight and card generation, worker execution, any model-based verification, and other provider work. Human review remains a separate measured component and is then added using a frozen time value.

Always publish raw review seconds. The proposal shows sensitivity at $25, $50, and $100 per hour and requires one value to be selected before a confirmatory run. Subscription usage, token-rate estimates, and actual provider charges must remain distinguishable.

## Measurement refinements now included

The local reference analyzer now includes three refinements identified during this planning pass:

1. Report approved-card versus full-context-worker directly, because that is the primary economic question.
2. Rename the current compression contrast to automatic card transformation.
3. Require provider usage components to reconcile with each condition's end-to-end totals, including the frontier preflight.

These refinements improve measurement only. They do not authorize the experiment or select the owner's acceptable quality loss.

## Control roles and delegated agency

The current implementation now names all three clutch-control roles in policy: the read-only Role Model, the human owner, and the trusted orchestrator. Workers and verifiers return evidence but cannot assign, reroute, approve, accept, or close work. An undeclared coordinator can no longer move a card merely by presenting a nonempty ID.

Prior explicit delegation can remain usable while the human is away. Human absence creates no new authority and does not automatically erase authority already invested in a frozen envelope.

A separate two-key extension is proposed but remains default-off and outside this study. It would permit the Role Model and orchestrator to perform one provisional, reversible local attempt only when both independently agree on the exact same card, current state, tests, and owner-delegated risk boundary. A disagreement returns to neutral, where the human breaks the tie. Publication, deployment, spending, destructive changes, permission expansion, undelegated secrets, external messages, and final acceptance remain outside that fallback.

This structure can bound additional authority, but it cannot guarantee that two correlated machine actors make no shared mistake. The extension needs its own adversarial fixtures and experiment after the human-approved route is stable.

## Pedal Protocol

The Pedal Protocol controls transfer depth. It tries the compact card first, then an expanded card with selected state or evidence, then full authorized context. It chooses the smallest package that passes every registered fit requirement. If nothing fits, work remains neutral. Full context is an acceptable coherence choice, but it carries no compression claim.

During the first shakedown this selector should run in shadow mode only. It records what it would have selected without changing the assigned four-arm condition. That preserves the experiment while giving us early evidence about whether a variable transfer policy is worth testing later.

Its memory loop is the Rotary Context Cycle: intake the current state, compress it to the smallest fitting package, run one attempt, emit a receipt, and carry observed error into a new card. A context-related failure must remain in the next cycle and blocks a smaller transfer unless new evidence resolves it. The rotary-engine language describes the repeating feedback cycle, not a claim that an automotive accelerator changes geometric compression.

## Decisions awaiting the owner

The recommendations are to use the full-context worker as the primary economic baseline, run only the five-task instrumentation stage first, scope later claims to long-context bounded builds, and keep Luna as a separate replication. The owner must still choose the quality margin and primary value for review time. The proposed two-key extension is a sixth, separate decision and does not alter the current four-arm test.
